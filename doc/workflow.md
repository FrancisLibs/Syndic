Principe directeur

La priorité absolue du logiciel est la fiabilité comptable.

La simplicité de l'interface, l'architecture du code et le workflow sont conçus pour garantir que les chiffres produits soient exacts, compréhensibles, vérifiables et transmissibles.

Décisions actées
Philosophie du logiciel

Construire un logiciel qui produit une comptabilité juste, explicable et compréhensible.

Principe n°1

Les chiffres doivent être justes.

La facilité de développement ne doit jamais primer sur la fiabilité comptable.

Principe n°2

Chaque chiffre doit pouvoir être expliqué.

On doit toujours pouvoir remonter jusqu'à son origine.

Principe n°3

Le logiciel guide le syndic.

Il ne se contente pas d'exécuter des commandes.

Principe n°4

Le logiciel prépare la transmission.

Il ne dépend pas de la mémoire de celui qui l'utilise.

Principe n°5

Le workflow est le cœur du module de clôture.

Toutes les fonctionnalités s'y intègrent.

Décisions techniques

✔ Repository → accès aux données

✔ Service → métier

✔ DTO → transport des données

✔ Controller → orchestration

✔ Twig → affichage

Aucune exception.
